01 / The Feature

What Dreaming actually is.

Until now, every AI agent forgot. You spend a week training a Claude agent for your workflow. It learns your style, your tone, the way you want emails written. The session ends. It forgets. Next session you start from scratch.

Dreaming flips that.

Definition

Dreaming is a scheduled background process that runs between agent sessions. It reviews past session transcripts, finds patterns the agent missed in real time, deletes outdated memory, merges duplicate entries, and writes a cleaner, smarter memory store for next time.

In plain English: your agent reviews yesterday and gets better overnight.

02 / Under the Hood

4 stages of a dream cycle.

Think of it like sleep for your agent. The brain replays the day, decides what to keep, throws out noise, and reorganises the rest. Same process, different substrate.

01

Replay

The dream job pulls up to 100 past session transcripts and the agent's current memory store. It reads everything end to end as raw material.

02

Pattern Extraction

It identifies recurring mistakes, workflows that converged, and stale facts — like a client preference that has since changed.

03

Memory Rewrite

Duplicates merge. Outdated entries get replaced. New patterns get added. The output is a brand new memory store — not an edit of the old one.

04

Handoff

Developers can let the new memory go live automatically or review it first. The original memory is never overwritten. You can roll back any time.

Important nuance: Dreaming does NOT retrain the model. It does not change weights. It is memory curation, not learning in the deep-learning sense. The agent gets smarter because it starts the next session with a cleaner, better-organised memory — not because the underlying model improved.

04 / The Shift

The static agent era is over.

For the last 18 months, every AI agency, every n8n freelancer, every Claude agent builder has been selling the same thing: a static workflow. You build it once, configure prompts, ship to client, charge a setup fee plus retainer for changes.

The problem: clients had to keep asking you to improve the agent. Every new edge case meant a new ticket. Every preference shift meant a new prompt. The agent never got better on its own. The agency became a maintenance bottleneck.

Dreaming kills the static agent. Now your agent compounds. Every session it runs adds to the pile of evidence it learns from overnight. The 30th week of operation is dramatically more useful than the first.

06 / The Fine Print

The risks nobody on LinkedIn is mentioning.

  • Bias amplification. If past sessions are skewed, the dream amplifies the skew. Example: a user corrects the agent 3 times in a row to use formal language for a legal doc. Dreaming may conclude "user always prefers formal" and apply it to a casual chat the next day.
  • Hallucinated memory. Pattern extraction is itself an LLM task. It can imagine patterns that were not there. This is why Anthropic keeps the original memory untouched and outputs a separate file for review.
  • Narrow validation. The 6x figure comes from one customer in one domain (legal drafting). It is a real number but it has not been replicated across every vertical yet. Treat domain-specific lift as the realistic expectation.
  • Cost. Dreaming runs at standard API token rates. Long session histories mean expensive dreams. Budget this in. Some teams will dream weekly instead of nightly to control cost.
  • Lock-in. Agents that have dreamed for 6 months become hard to replace. That is great for you if you built them. It is a trap for clients who want to switch providers later. Be transparent about this.

The Takeaway

Dreaming is not magic. It is memory curation done well, on a schedule, with measurable lift. But that is enough to break the static agent business model that most of the AI agency economy is built on.
